Testing AI agents: what changes when the software talks back

Classic test automation assumes the same input gives the same output. Agents break that assumption. Here is how we test them anyway.

All In·2 November 2026·5 min read

A conventional test is a simple promise: given this input, the system produces that output. An AI agent breaks the promise on purpose. Ask it the same question twice and you will get two differently worded answers, both possibly correct. Teams used to exact-match assertions often conclude that agents cannot be tested. They can. The tests just check different things.

Test behaviour, not wording

Instead of asserting the exact reply, assert properties of it. Did the agent state the correct price? Did it avoid naming a medicine? Did it collect the phone number and read it back? Each property is a yes or no question that can be checked automatically, by rules where possible and by a second model acting as a grader where judgement is needed.

Write scenarios, not single prompts

Real conversations have turns. A caller changes their mind, answers a different question from the one asked, or switches language halfway through. A useful test set is made of short scripted scenarios with a goal and a persona, not isolated questions. We keep three kinds: ordinary requests, awkward but legitimate ones, and attempts to push the agent past its limits.

Give refusals their own suite

Every rule about what the agent must not do deserves at least a handful of tests that actively try to make it do that thing. These are the tests that matter most and the ones most likely to regress when someone "improves" a prompt. Run them on every change, without exception.

Run each test more than once

Because outputs vary, a single pass tells you little. Run each scenario several times and look at the pass rate. A behaviour that holds nine times out of ten is a defect in a safety rule and may be acceptable in a matter of tone. Decide the threshold per test, in advance.

Test the hand-over, not just the conversation

The agent's real output is rarely the chat itself. It is the record that lands in front of a member of staff: the request, the contact details, the summary. Check that the record is complete and correct, because that is where a polite conversation turns into a missed appointment.

Keep reading real transcripts

No test set anticipates everything. A regular review of real conversations, with permission and with personal details handled properly, is where new scenarios come from. Every surprising transcript becomes a test, and the suite grows in the direction reality pushes it.

None of this replaces ordinary testing. The integrations around the agent, the telephony, the queue, the notifications, still need conventional automated tests. The agent adds a layer on top, and that layer needs its own discipline.
